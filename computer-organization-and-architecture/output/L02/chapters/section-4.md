# 04 指令集与RISC设计

[本讲目录](../index.md) · [课程目录](../../index.md) · [上一节：03 性能汇总与优化收益](section-3.md) · [下一节：05 寄存器与指令编码](section-5.md)

## ISA的软件硬件接口

指令集体系结构（ISA）定义处理器对软件呈现的指令、可见资源及其机器编码。软件依据这套规则编译，硬件依据同一规则执行；不同微架构可以实现相同ISA。[^s1p31][^s1p35]

抽象层次从高到低为：应用软件、操作系统、ISA、微架构、逻辑、数字电路、模拟电路、工艺与器件、物理。操作系统提供线程、文件等服务并管理资源；ISA规定机器操作的语义；微架构决定用什么流水线、执行单元和调度方式实现这些语义。[^s1p30][^s2b8]

典型代码转换关系是高级语言到汇编，再由汇编器编码为机器语言。例如，`x=a+b`可以转化为寄存器加法，再编码成处理器能够解码的二进制位。汇编文字与机器编码是同一指令的不同表示。[^s1p31]

好ISA应保持概念完整性：规则尽量简单、直接、统一，让使用者容易理解，也让实现者减少特殊情况。[^s1p32][^s1p33][^s1p34]

| 抽象要求 | 目的 |
| --- | --- |
| 可移植性 | 同一接口跨多代实现保持可用 |
| 通用性 | 适用于多种应用场景 |
| 上层便利 | 软件能方便表达所需功能，编译器容易生成代码 |
| 下层高效 | 硬件可以有效实现，控制成本、性能与能耗 |

## 数据通路与控制

处理器组织可以分为数据通路（datapath）与控制（control）。数据通路包含执行指令所需的功能单元、寄存器等存储部件及互联；控制决定这些部件何时做什么、数据从哪里流向哪里。[^s1p36]

指令执行的基本过程为：

1. 根据程序计数器PC从内存取入指令。
2. 解码操作和操作数，产生控制信号。
3. 让功能单元完成运算；需要时访问数据内存。
4. 将结果写回相应寄存器或存储位置。
5. 更新指令执行位置，选择后续指令。[^s1p36][^s2b9]

算术逻辑、数据传送和控制流指令分别作用于运算、数据访问和后续指令选择。[^s1p44]

## CISC与RISC的权衡

复杂指令集计算机（CISC）偏向用功能较丰富的指令表达工作。早期内存昂贵而容量小、程序员常直接编写汇编，这使代码密度和编程便利十分重要。变长编码和复合操作可以减少某些程序的指令数量，但复杂操作也增加译码、控制状态机和执行过程的负担。[^s1p37][^s2b9]

精简指令集计算机（RISC）的典型设计取向是规则的基本指令长度、load-store结构、有限寻址模式和相对简单的操作。load-store结构把内存访问与寄存器运算分开：运算先在寄存器中进行，数据通过专门的load/store指令进出内存。[^s1p38]

以`a=a*b`为例，示意CISC可用一条复合指令，而示意RISC分为四步：[^s1p37][^s1p38]

```text
LOAD A, 2:3    # 从a所在内存读入寄存器A
LOAD B, 5:2    # 从b所在内存读入寄存器B
PROD A, B      # A = A * B
STORE 2:3, A   # 写回a
```

上述为示意汇编。两种方案的执行时间仍取决于$IC\times CPI\times CC$；简单指令可以用较低CPI或较短周期补偿指令条数。[^s2b10]

外部ISA与内部执行方式也可以不同。x86处理器可把复杂机器指令转换为内部的RISC-like微操作，再采用流水线、调度等技术执行。SoC和移动设备还特别关注芯片面积与能耗，这也是简单、规则执行结构的重要应用背景。[^s1p39]

## RISC-V的开放与模块化

RISC-V读作“risk-five”，是开放的RISC类ISA标准，起源于2010年加州大学伯克利分校的研究工作。开放的是指令集规范；实现可以是开源设计，也可以是商业芯片。[^s1p40][^s2b10]

规范不强制一种微架构或实现技术：顺序执行、乱序执行、微码方式，以及ASIC或FPGA实现，都可以遵守相同指令语义。小型基础整数ISA既可独立用于教育和定制加速器，也可配合标准扩展或自定义扩展支持更复杂的软件。浮点相关设计支持IEEE 754标准。[^s1p41]

ISA名称通常由`RV + 数据字长 + 扩展标识`组成。例如，`RV32I`表示32位整数寄存器与I基础整数指令集；本讲后续主要使用RV64的64位数据寄存器。数据字长与指令编码长度是不同概念。[^s1p42][^s2b11]

| 标识 | 含义 |
| --- | --- |
| I | 基础整数运算、分支与跳转、load/store |
| M | 整数乘法和除法 |
| A | 原子操作 |
| F | 单精度浮点 |
| D | 双精度浮点 |
| C | 16位压缩指令，改善代码密度 |

用户级规范描述普通计算指令，特权级规范描述操作系统等特权软件需要的功能；压缩编码支持较短指令。C扩展的16位指令可与基本32位指令共存。[^s1p42][^s1p43]

历史介绍中G缩写为IMAFD；现行规范中G还包含Zicsr和Zifencei，具体名称应对应所用规范版本。[^s1p43] [RISC-V官方指令表](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv-32-64g.html)

## 四项设计原则

RISC-V的基本设计体现四个相互配合的方向。[^s1p73]

- **简单促成规则性**：基础指令采用32位编码，保持较少的格式，便于解码。
- **好设计需要折中**：六种常用格式分别适应寄存器运算、立即数、存储和控制流等需求。
- **较小规模有利速度**：限制寄存器规模、寻址模式和不必要的复杂操作，减少硬件负担。
- **让常见情况更快**：算术操作数来自寄存器，常用小常数直接包含在指令中，避免额外内存读取。[^s2b15]

## 应用问答

**问：两个CPU都执行RV64I，一个顺序执行、一个乱序执行，为什么仍能运行相同机器代码？**

答：它们遵守同一ISA语义；指令如何调度和执行属于微架构实现。[^s1p41]

**问：RV64支持C扩展，是否说明所有指令都是64位或16位？**

答：64指数据字长；基本指令为32位，C扩展提供部分16位压缩编码。[^s1p42][^s2b11]
