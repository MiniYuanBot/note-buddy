# 05 多周期实现

[本讲目录](../index.md) · [课程目录](../../index.md) · [上一节：04 单周期数据通路](section-4.md) · [下一节：06 流水线组织与性能](section-6.md)

## 分步执行与资源复用

多周期处理器把一条指令拆成若干较短步骤，每一步占一个周期，上一条结束后才开始下一条。它通过不同周期重复使用同一功能单元，减少单周期实现所需的资源复制。[^s1p56][^s1p130]

设计时应尽量平衡各步骤的工作量，并使每周期只进行一次主要存储器访问或ALU运算。例如取指周期用ALU算PC+4，地址计算周期用同一ALU算基址加偏移，两次运算不同时发生；同一块存储器也可先取指，稍后读写数据。[^s1p59][^s2b10]

## 指令需要多少周期

各步骤及指令完成点如下：[^s1p57][^s1p134]

| 步骤 | 基本工作 | 指令完成点 |
|---|---|---|
| IF | 取指并更新PC | — |
| ID | 译码、读寄存器、生成符号扩展立即数 | — |
| EX | R型运算，load/store地址计算，或分支比较及跳转 | 分支完成 |
| 第4步 | load读存储器，store写存储器，或R型回写寄存器 | store、R型完成 |
| WB | 将load读出的数据写回寄存器 | load完成 |

因此该设计中load为5周期，store为4周期，R型为4周期，分支为3周期。R型的第4步是回写寄存器。[^s2b9]

**补充解释**：若依次执行一条load、一条store和一条R型运算，没有其他等待，则一共需要 $5+4+4=13$ 个多周期时钟。每条结束后才取下一条，不能按流水线重叠计算。

## 内部寄存器保留中间结果

拆分步骤后，本周期产生而下周期还要使用的数据必须在周期末保存，否则输入变化后组合逻辑输出也会变化。多周期数据通路因此增加内部状态寄存器。[^s1p58]

| 内部寄存器 | 保存内容 | 后续用途 |
|---|---|---|
| IR | 当前指令 | 多个周期的译码、源/目标字段和控制 |
| MDR | 存储器读出数据 | load最后回写 |
| A、B | 寄存器堆的两个读出值 | ALU操作数或store数据 |
| ALUout | ALU结果 | 访存地址或运算回写 |

这些状态不直接出现在ISA中。供后续指令观察的结果最终写到程序可见的寄存器堆、PC或存储器。[^s1p59][^s1p131]

IR必须跨越整条指令的执行过程，因此只在取指时写入，使用IRWrite控制。该示意设计中的其他内部寄存器只需在相邻周期之间传递有效数据，可每周期更新；是否使用其内容由当时的控制路径决定。[^s1p131]

以load为例：

1. IF把读出的指令存入IR。
2. ID把基址寄存器值存入A，并解出立即数。
3. EX将 $A+\operatorname{sext}(imm)$ 保存到ALUout。
4. 访存周期用ALUout作为地址，将读出值保存到MDR。
5. WB选择MDR回写IR指定的rd。[^s1p60][^s1p134]

## 多路选择与状态写控制

复用部件需要额外MUX来选择“这一周期”的输入：存储器地址可来自PC或ALUout，ALU第一输入可来自PC或A，第二输入可来自B、常量4或立即数，回写数据可来自ALUout或MDR。[^s1p63][^s1p132]

PC也不再每周期无条件更新。PCWrite允许无条件写，PCWriteCond允许在分支条件成立时写；对beq型条件，写使能可由 $PCWrite\lor(PCWriteCond\land Zero)$ 形成。PCSource选择顺序地址或跳转目标。[^s1p63]

这些写使能与MUX选择必须彼此配合。例如访存周期应以ALUout寻址，而不能把此时已更新的PC误当作load数据地址。

## 有限状态机控制

多周期控制需要知道**指令类型和当前执行状态**。opcode能说明是load还是store，却不能单独说明此周期该算地址、访问存储器还是回写。[^s1p61][^s1p133]

有限状态机（FSM）包含：

- 状态集合与保存当前状态的状态寄存器。
- 下一状态函数，根据当前状态及输入决定下一步。
- 输出函数，产生当前步骤所需的运算、MUX和写使能控制。

基本状态路径可表示为：

```text
取指 → 译码 → 地址计算 → load读存储器 → load回写 → 取指
                    └→ store写存储器 ─────────→ 取指

取指 → 译码 → R型运算 → R型回写 → 取指
取指 → 译码 → 分支比较及完成 → 取指
```

在示例状态编号中，地址计算是状态2；load随后进入状态3读存储器，再到状态4回写；store进入状态5写存储器，然后回到取指状态0。这些编号是FSM状态名。[^s1p62][^s2b10]

## 周期效率与实现代价

多周期时钟由最慢的单个步骤约束，而不是整条最慢指令；较短指令还可以少执行几个步骤。例如store不需要load的最终回写周期。[^s1p64][^s1p135]

把单周期拆成5步，并不保证每步周期恰好缩短为原来的五分之一：每一步都要经过内部寄存器的输出延迟和建立时间，步骤还可能不均衡。单条load可能因这些额外开销而更慢；是否提升程序性能取决于各指令出现比例、平均周期数和新周期长度。[^s1p55][^s1p136][^s2b9]

资源复用可减少存储器和加法器数量，但新增内部寄存器、MUX及FSM控制会增加设计复杂度。[^s1p64][^s1p135]

## 自测问答

**问**：为什么R型与store都用4周期，却不能让它们的第4步执行相同控制？

**答**：R型需要RegWrite写运算结果，store需要MemWrite写存储器。周期数相同不代表状态更新相同。

**问**：load在第4周期已从存储器读到数据，为什么还需要MDR和第5周期？

**答**：读出值先在周期末保存在MDR，下一个周期才能沿回写路径稳定送入寄存器堆，完成分开的回写步骤。
