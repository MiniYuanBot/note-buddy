# 06 流水线组织与性能

[本讲目录](../index.md) · [课程目录](../../index.md) · [上一节：05 多周期实现](section-5.md) · [下一节：07 冒险检测与处理](section-7.md)

## 重叠执行提高吞吐

流水线在一条指令尚未完成时就开始下一条，让不同指令同时占据不同阶段。吞吐率是单位时间完成的指令数；延迟是一条指令从开始到完成所需时间。流水线主要提高吞吐，并不保证减少单条延迟。[^s1p65][^s1p138]

食堂分工可作简短类比：一个人依次盛完饭、汤和配菜再服务下一个人，是顺序执行；不同窗口同时为不同人完成各步骤，就能提高持续出餐速度。[^s1p67]

基本五级流水为IF取指、ID译码和读寄存器、EX运算或算地址、MEM访存、WB回写。R型在MEM不访存，store在WB不回写，但仍按固定阶段时序通过流水线。[^s1p138][^s1p140]

## 并发需要的资源

同一周期的IF与MEM可能分别取指和访问数据，因此分离指令/数据存储器；IF更新PC、EX做数据运算及分支地址计算也需要独立运算资源。多周期实现里能复用的部件，在流水线中可能要同时工作。[^s1p68][^s1p69]

寄存器堆可用不同读写端口支持ID与WB共存。在本模型中，WB在周期前半写入，ID在后半读取，因此同一周期读写同一寄存器时能读到刚写入的值。[^s1p70]

## 流水寄存器携带指令状态

相邻阶段之间分别有IF/ID、ID/EX、EX/MEM和MEM/WB流水寄存器。每个名称表示连接的两个阶段；其中包含多项字段，而不是只能存一个数的单寄存器。[^s1p71]

| 边界 | 需要携带的信息示例 |
|---|---|
| IF/ID | 指令、该指令对应的PC |
| ID/EX | 读出的源值、立即数、源/目标寄存器号、后续控制 |
| EX/MEM | ALU结果或地址、store写数据、目标寄存器号、MEM/WB控制 |
| MEM/WB | load数据或ALU结果、目标寄存器号、WB控制 |

只要后续阶段还需要某个值，就必须逐级保存。例如store的数据来自rs2，沿流水寄存器到MEM写数据端；其地址来自ALU加法结果，两者不能混淆。[^s1p71][^s2b10]

rd也必须随产生结果的指令传到WB。WB所回写的是较早进入流水线的指令，不能直接使用当前IF或ID指令的rd。[^s1p72]

## 控制信号随指令传播

控制器在ID依据指令生成信号，再将尚未使用的信号连同数据一起送到后续阶段。一个阶段使用完的控制不必再传；仍待使用的控制必须保持与原指令对应。[^s1p73][^s2b11]

| 使用阶段 | 控制含义 |
|---|---|
| EX | ALUSrc选择操作数，ALUOp确定运算 |
| MEM | MemRead、MemWrite决定存储器访问；晚决定分支的实现还保留分支控制 |
| WB | RegWrite决定是否回写，MemtoReg选择回写数据 |

EX/MEM保留MEM和WB控制，MEM/WB只需保留WB控制。MIPS教学图中的RegDst在EX选择目标字段；RISC-V写整数结果时使用固定位置的rd。[^s1p73]

## 填充、稳态与排空

流水线深度是阶段数。五级流水执行以下互不依赖的指令序列时，前4周期尚在填充，第5周期五条分别占据五个阶段，随后逐步排空：[^s1p74]

```asm
lw  x8,  4(x29)
sub x2,  x4,  x5
and x9,  x10, x11
or  x16, x17, x18
add x13, x14, x0
```

| 指令 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| lw | IF | ID | EX | MEM | WB | | | | |
| sub | | IF | ID | EX | MEM | WB | | | |
| and | | | IF | ID | EX | MEM | WB | | |
| or | | | | IF | ID | EX | MEM | WB | |
| add | | | | | IF | ID | EX | MEM | WB |

五条总共9周期。第5周期EX处理第三条and，ID处理第四条or，WB完成第一条load；从第5周期起连续完成一条指令。[^s1p75][^s1p79]

**补充解释**：对每周期启动一条、无停顿的 $k$ 级流水，第一条需 $k$ 周期，之后每条多1周期，所以 $N$ 条共 $N+k-1$ 周期：

$$
\mathrm{CPI}_{\rm 有限序列}=\frac{N+k-1}{N}
=1+\frac{k-1}{N}.
$$

$N$ 很大时填充排空摊销很小，CPI趋近1；五条五级的平均CPI却为 $9/5=1.8$，不能把稳态结论直接当成短序列总时间。[^s1p89]

## 延迟和吞吐的数值比较

给定阶段延迟如下，先忽略额外流水寄存器开销：[^s1p81]

| IF | ID | EX | MEM | WB |
|---|---|---|---|---|
| 1.0ns | 0.6ns | 0.9ns | 1.2ns | 0.4ns |

单周期将各环节串联，周期为 $1.0+0.6+0.9+1.2+0.4=4.1$ ns。五级流水的所有阶段使用同一周期，最慢MEM决定周期为1.2ns。[^s1p81]

| 指标 | 单周期 | 五级流水 |
|---|---|---|
| 周期长度 | 4.1ns | 1.2ns |
| 单条周期数 | 1 | 5 |
| 单条延迟 | 4.1ns | 6.0ns |
| 持续完成间隔 | 4.1ns | 1.2ns |

流水的单条延迟增加，却可在填满后每1.2ns完成一条，所以稳态吞吐加速为：

$$
\mathrm{Speedup}=\frac{4.1}{1.2}\approx3.42.
$$

阶段不平衡是未达到理想5倍的原因；真实设计还需加上寄存器时序开销。[^s1p80][^s1p82][^s1p83]

**补充解释**：上述五条序列若与五条单周期执行比较，总时间分别为 $9\times1.2=10.8$ ns与 $5\times4.1=20.5$ ns，加速约1.90倍，小于稳态3.42倍，因为序列较短。

## 深度、功耗与性能边界

理想平衡阶段且无额外开销时，$k$ 级流水吞吐可以提高约 $k$ 倍。不断增加深度却会增加流水寄存器数量和开销；冒险带来的停顿也会使“每周期一条”失效。[^s1p83][^s1p86][^s1p137]

x86历史示例中，流水深度从i486约5级增至Pentium4 Prescott约31级，随后Core2 Conroe回到约14级，之后的示例约16级。功耗、时序及冒险代价共同限制加深流水的收益，阶段数必须对应具体实现。[^s1p84][^s2b11]

降低功耗可采用以下机制：[^s1p85][^s2b11]

- **时钟门控**：停止闲置部分的时钟翻转，减少相关动态活动。
- **利用时序余量降电压**：若数据稳定后距离采样边沿仍有slack，可在满足时序的前提下降低电压；降低电压会减小开关能耗，但也可能增加传播延迟。
- **异步设计**：以局部事件协调工作，减少对统一时钟的依赖。

比较程序运行时间仍需使用：

$$
\mathrm{CPU\ time}=IC\times CPI\times CC,
$$

其中IC是动态指令数，CPI是平均每条周期数，CC是周期长度。加深流水可能缩短CC，也可能增加CPI；要比较两者乘积，不能仅看频率。超标量进一步尝试每周期取入并执行多条指令。[^s1p137]

本节的32位基本指令、固定寄存器字段、只在load/store访问内存、整数结果指令至多写一个目标寄存器，都有利于固定阶段组织。该简化长度假设不包含压缩指令扩展。[^s1p142]

## 自测问答

**问**：五条无依赖指令通过五级流水，第4周期ALU执行哪一条，整体何时结束？

**答**：ALU在EX执行第二条；第五条在第9周期WB结束，总共9周期。

**问**：表中的流水单条延迟6ns大于4.1ns，为何长程序仍可能更快？

**答**：流水允许多条重叠执行，稳态完成间隔从4.1ns降为1.2ns；吞吐提高，而非单条延迟降低。
