# 05 处理器与并行

[本讲目录](../index.md) · [课程目录](../../index.md) · [上一节：04 存储层次与内存墙](section-4.md) · [下一节：06 功耗与系统能效](section-6.md)

## 指令执行的基本路径

处理器通过取指、译码、控制和执行，把机器指令变成数据操作。缓存、寄存器与运算单元为这一过程提供指令、操作数和结果存放位置。[^s1p39][^s2b13]

1. **取指（Fetch）**：从指令存储路径取得下一条指令。需要访问主存时，通过系统互连把指令送到处理器的缓存体系。
2. **译码（Decode）**：识别指令要求的操作及相关操作数。
3. **控制（Control）**：根据指令安排数据读取、运算与结果写入。
4. **执行**：算术逻辑单元（ALU）执行整数算术与逻辑操作，浮点单元（FPU）处理浮点运算；寄存器提供操作数并保存结果。
5. **数据访问与结果保存**：按指令要求写寄存器或经数据存储路径访问内存。[^s1p39][^s2b13]

其中，`load`把内存数据读入处理器，`store`把处理器中的数据写到内存地址。缓存位于处理器与主存之间；一次访问实际走到哪一级，取决于数据所在位置和缓存策略。[^s2b13]

## 相近频率下提高性能

提高性能还可以依靠每个周期完成更多有效工作。执行单元的组织、缓存供给和指令调度，决定硬件能否充分利用已有运算能力。芯片布局示例把执行单元、指令调度与退休、L1指令缓存、L1数据缓存和L2缓存列为主要部分。[^s1p44][^s1p45]

**补充解释**：指令调度决定何时把已具备执行条件的指令交给执行单元；退休表示把已经完成的指令结果确认为程序状态的一部分。

并行可以发生在不同层次：[^s2b2]

| 层次 | 同时推进的工作 |
| --- | --- |
| 指令级并行 | 同一程序中的多条指令 |
| 数据级并行 | 多份数据上的同类操作 |
| 线程级并行 | 多个线程的执行 |

各层并行需要相应的软件与硬件支持。指令级并行涉及编译与微架构，线程级并行则需要把工作安排到多个执行核心。[^s2b2]

## 多核芯片的组成

Coffee Lake芯片示例中，六个CPU核心围绕共享L3缓存与环形互连组织；旁边还有系统代理与内存控制器、内存控制器I/O、处理器图形单元，以及显示和其他I/O。[^s1p46]

多核系统的关键问题是如何连接核心、协调共享数据，并把线程安排到合适的位置。[^s1p47]

| 问题 | 需要解决的任务 |
| --- | --- |
| 核间互连 | 在各核心和共享资源之间传输数据 |
| 缓存与内存一致性 | 协调多个核心观察共享数据的方式 |
| 线程调度 | 将线程分配给执行核心 |
| 线程同步 | 协调多个线程的执行进度和共享操作 |
| 缓存亲和性 | 在调度时考虑线程已有数据位于哪些缓存中 |

**补充解释**：缓存一致性（coherence）主要约束同一地址的缓存副本；内存一致性（consistency）约束多个内存访问可被观察到的顺序。线程迁移到另一核心后，原核心缓存中已有的数据可能需要重新取得，这就是缓存亲和性影响调度的一个原因。

## 共享资源与大工作集

多个核心共享DRAM时，系统不仅要满足总数据容量，还要让各核心及时获得数据。大工作集会增加内存需求，多个线程同时执行也会给数据服务路径带来更多请求。存储设备同样需要在性能与共享方式上配合多核执行。[^s1p48]

## 应用问答

**问**：一条`store`指令与一条`load`指令的数据方向有何不同？

**答**：`store`把处理器数据写到内存地址，`load`把内存数据读到处理器；两者都可能使用缓存路径。

**问**：线程频繁换核心后性能下降，除了线程本身的计算量，还应检查什么？

**答**：检查缓存亲和性：迁移后是否失去原核心缓存中的已有数据，以及重新取数据带来的代价。
